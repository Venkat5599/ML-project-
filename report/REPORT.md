## 1. Problem Statement

Cryptocurrency transaction networks allow funds to move rapidly across
interconnected addresses, which makes laundering activity hard to identify with
per-transaction rules alone. Rule-based systems produce high false-positive
rates and cannot adapt to new laundering patterns.

This project asks: *can combining transaction-level features with
wallet-network structure detect suspicious cryptocurrency activity more
effectively than conventional tabular ML models, while explaining why a
transaction was flagged?*

The system output is a **ranked suspicion score** for each transaction, not a
determination of criminality. A flagged transaction is a candidate for human
review; ground-truth confirmation requires off-chain evidence the dataset does
not contain.

### Scope and limitations

- Labels come from the dataset vendor's attribution (exchanges, darknet
  markets, ransomware, etc.). They are incomplete: 77% of transactions are
  unlabeled. Unlabeled transactions are **never** treated as licit.
- Detection is evaluated only on labelled data; real-world performance on the
  unlabeled 77% cannot be measured and is a stated limitation.

## 3. Dataset and Exploratory Data Analysis

**Dataset:** Elliptic Bitcoin dataset (Kaggle; HuggingFace mirror used for
reproducibility). 203,769 transaction nodes, 234,355 directed edges, 49
two-week time steps, 165 anonymized features per transaction (93 local +
72 one-hop aggregates), labels: licit (42,019), illicit (4,545),
unknown (157,205).

Key EDA findings (see `results/figures/`):

1. **Class imbalance.** Among labelled transactions the licit:illicit ratio is
   9.25:1; including unlabeled data the illicit share is ~2.2%. Accuracy is
   therefore a misleading metric; precision-recall metrics are primary.
   *(figure: class_distribution.png)*
2. **Temporal drift.** The illicit share of labelled transactions varies from
   ~0% to ~27% across time steps and drops markedly in the test window — the
   detection task genuinely gets harder over time.
   *(figure: labels_over_time.png)*
3. **Feature separability.** Local features dominate separability
   (top Cohen's d: `local_53` = 1.16, `local_55` = 1.00, `local_89` = 0.99);
   aggregated neighbour features carry weaker univariate signal.
   *(figure: top_feature_boxplots.png)*
4. **Correlation/redundancy.** A block of strongly intercorrelated features
   motivates the full-vs-reduced feature experiment.
   *(figure: correlation_heatmap.png)*
5. **Graph topology.** The graph decomposes into exactly 49 weakly-connected
   components — one per time step (edges do not cross time periods).
   Degree distributions are heavy-tailed (max in-degree 284, out-degree 472),
   consistent with hub transactions. Neighbourhood illicit rate is bimodal:
   labelled neighbours of illicit transactions are disproportionately illicit,
   supporting the graph-homophily hypothesis.
   *(figures: degree_distribution.png, neighbourhood_illicit_rate.png)*

## 4. Proposed Solution

```
raw CSVs -> dataset join -> temporal split (1-29 train / 30-34 val / 35-49 test)
  -> [supervised]  LR, Decision Tree, Random Forest, XGBoost, SVM
  -> [anomaly]     Isolation Forest, Autoencoder (fit on licit train only)
  -> [later phase] graph-derived features, GraphSAGE, hybrid ensemble, SHAP
  -> ranked alerts + explanations -> investigation dashboard (later phase)
```

Methodology controls:

- Temporal split prevents future-information leakage; a random split is run
  only as a comparison experiment to quantify its optimism.
- Class imbalance handled via `class_weight`/`scale_pos_weight`, not resampling.
- Tuning uses Optuna (TPE) maximizing **average precision** on the validation
  slice; the test window is evaluated once.
- Metrics: precision, recall, F1, average precision (PR-AUC), ROC-AUC,
  Precision@K / Recall@K for K = 50, 100, 250, and batch inference time.

## 6. Discussion

- Which family won on which metric, and why that matters for an investigation
  queue (Precision@K vs recall trade-off).
- The anomaly-detection negative result: unsupervised scores did not align with
  illicit labels in feature space, consistent with laundering transactions
  mimicking normal flows; their role is complementary (novel-pattern coverage),
  not primary detection.
- Threats to validity: incomplete labels, unknown-labelled contamination of
  the anomaly training set is avoided by fitting on labelled licit only;
  aggregated features may encode future-graph information (documented).
