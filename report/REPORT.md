## 1. Problem Statement

Cryptocurrency transaction networks allow funds to move rapidly across
interconnected addresses, which makes laundering activity hard to identify with
per-transaction rules alone. Rule-based systems produce high false-positive
rates and cannot adapt to new laundering patterns.

This project asks: *can combining transaction-level features with
wallet-network structure detect suspicious cryptocurrency activity more
effectively than conventional tabular ML models, while explaining why a
transaction was flagged?*

The system output is a **ranked suspicion score** for each transaction, not a
determination of criminality. A flagged transaction is a candidate for human
review; ground-truth confirmation requires off-chain evidence the dataset does
not contain.

### Scope and limitations

- Labels come from the dataset vendor's attribution (exchanges, darknet
  markets, ransomware, etc.). They are incomplete: 77% of transactions are
  unlabeled. Unlabeled transactions are **never** treated as licit.
- Detection is evaluated only on labelled data; real-world performance on the
  unlabeled 77% cannot be measured and is a stated limitation.

## 3. Dataset and Exploratory Data Analysis

**Dataset:** Elliptic Bitcoin dataset (Kaggle; HuggingFace mirror used for
reproducibility). 203,769 transaction nodes, 234,355 directed edges, 49
two-week time steps, 165 anonymized features per transaction (93 local +
72 one-hop aggregates), labels: licit (42,019), illicit (4,545),
unknown (157,205).

Key EDA findings (see `results/figures/`):

1. **Class imbalance.** Among labelled transactions the licit:illicit ratio is
   9.25:1; including unlabeled data the illicit share is ~2.2%. Accuracy is
   therefore a misleading metric; precision-recall metrics are primary.
   *(figure: class_distribution.png)*
2. **Temporal drift.** The illicit share of labelled transactions varies from
   ~0% to ~27% across time steps and drops markedly in the test window — the
   detection task genuinely gets harder over time.
   *(figure: labels_over_time.png)*
3. **Feature separability.** Local features dominate separability
   (top Cohen's d: `local_53` = 1.16, `local_55` = 1.00, `local_89` = 0.99);
   aggregated neighbour features carry weaker univariate signal.
   *(figure: top_feature_boxplots.png)*
4. **Correlation/redundancy.** A block of strongly intercorrelated features
   motivates the full-vs-reduced feature experiment.
   *(figure: correlation_heatmap.png)*
5. **Graph topology.** The graph decomposes into exactly 49 weakly-connected
   components — one per time step (edges do not cross time periods).
   Degree distributions are heavy-tailed (max in-degree 284, out-degree 472),
   consistent with hub transactions. Neighbourhood illicit rate is bimodal:
   labelled neighbours of illicit transactions are disproportionately illicit,
   supporting the graph-homophily hypothesis.
   *(figures: degree_distribution.png, neighbourhood_illicit_rate.png)*

## 4. Proposed Solution

```
raw CSVs -> dataset join -> temporal split (1-29 train / 30-34 val / 35-49 test)
  -> [supervised]  LR, Decision Tree, Random Forest, XGBoost, SVM
  -> [anomaly]     Isolation Forest, Autoencoder (fit on licit train only)
  -> [later phase] graph-derived features, GraphSAGE, hybrid ensemble, SHAP
  -> ranked alerts + explanations -> investigation dashboard (later phase)
```

Methodology controls:

- Temporal split prevents future-information leakage; a random split is run
  only as a comparison experiment to quantify its optimism.
- Class imbalance handled via `class_weight`/`scale_pos_weight`, not resampling.
- Tuning uses Optuna (TPE) maximizing **average precision** on the validation
  slice; the test window is evaluated once.
- Metrics: precision, recall, F1, average precision (PR-AUC), ROC-AUC,
  Precision@K / Recall@K for K = 50, 100, 250, and batch inference time.

### 5.4 Ablation and comparison experiments

| experiment | result | interpretation |
|---|---|---|
| XGBoost, random split vs temporal split | AP 0.986 vs 0.801 | random splitting inflates AP by ~18 points — temporal leakage optimism quantified |
| XGBoost, top-30 features vs all 165 | AP 0.784 vs 0.801 | most signal sits in ~30 features; slight loss at high compression |
| XGBoost + hand graph features | AP 0.802 vs 0.801 | no gain — dataset's 72 aggregated features already encode one-hop structure |
| GraphSAGE alone | AP 0.599, P@100 0.970 | weaker under temporal drift than tuned XGBoost, but its top-100 remains ~97% pure |
| Ensemble vs best single model | F1 0.815 vs 0.796; AP 0.797 vs 0.801 | no AP gain; best F1 and equal top-K precision — robustness rather than dominance |

### 5.5 Explainability

`results/figures/shap_summary_xgb.png` — SHAP on the tuned XGBoost model:
`local_53`, `local_59`, `local_46`, `local_90`, `local_67` are the dominant
attributions, consistent with the univariate separability analysis in §3.
Aggregated neighbour features contribute materially less, explaining why
hand-crafted topology features add nothing on top.

## 6. Discussion

- **XGBoost is the strongest single detector** in both validation and test
  windows, and keeps precision = 1.0 across the top-100 alert queue — the
  operationally relevant region.
- **The ensemble is a robustness play, not an AP win.** It matches XGBoost's
  top-K precision while achieving the best F1 (0.815), hedging against
  single-model failure modes — which is what an investigation queue actually
  benefits from. Claiming more than that would not survive these experiments.
- **Temporal evaluation changes the headline.** The identical pipeline scores
  AP 0.986 under random splitting but 0.801 under chronological splitting —
  the honest number is the lower one. The test window also has lower illicit
  prevalence (6.5% vs ~17% in validation), so the drop reflects real drift,
  not overfitting.
- **Anomaly detection does not recover the illicit labels** (AP ≈ 0.04).
  Laundering transactions are engineered to look normal in feature space, so
  unsupervised scores serve as a secondary signal (14% ensemble weight) rather
  than a primary detector.
- **The GNN's value is in its top of ranking**, not overall AP: P@100 = 0.97
  despite AP 0.60. Label-propagation through message passing picks up a
  different subset of illicit transactions than feature-space boosting.
- **Threats to validity.** (a) Labels are incomplete and vendor-attributed;
  unknown labels were never used as ground truth. (b) The dataset's aggregated
  features may encode future-graph information — a documented dataset caveat,
  not something we introduced. (c) Graph features are transductive (computed
  on the full edge set, which is observable at deployment).

## 7. Conclusion

We built a leakage-safe, temporal AML pipeline over the Elliptic dataset:
203k transactions, 234k flows, 49 time steps, 9.25:1 class imbalance. Across
supervised, unsupervised, and graph-based methods evaluated under a single
protocol, a tuned XGBoost model is the best ranker (AP 0.801, P@100 1.0 on the
held-out test window), and a tuned weighted ensemble delivers the best F1
(0.815) with identical top-of-queue precision. SHAP attributions and per-alert
explanations are served through an investigation dashboard that also exposes
the 50,834 unlabeled test-window transactions ranked by calibrated suspicion.

Future work: temporal GNNs (EvolveGCN), learned node embeddings as tabular
features, cost-sensitive threshold selection, and the optional AMLSim
controlled experiment.
